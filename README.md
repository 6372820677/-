## 一、任务与环境

在已有任务看板上完成一个异步缺陷修复、一个URL状态功能及自动化测试。页面已有搜索、状态筛选、六项一页的分页、加载/错误/空态。搜索仅匹配任务标题，去首尾空白、不区分大小写；筛选不会改变原任务顺序。

环境准备在开考前完成：Node 22.12+（推荐使用仓库.nvmrc的22系列）、npm、现代浏览器。

```bash
git clone https://github.com/LUOLIN926/taskboard-exam-base.git
cd taskboard-exam-base
git checkout exam-v1
npm ci
npm test
npm run dev
```

运行和测试不依赖外部服务，依赖提前准备；编程期间可以访问AI、资料和推送GitHub。`npm run build`生成生产资源，`npm run preview`可检查构建结果。

## 二、种子与代码导览

24项任务，ID 1至24，每页6项。状态为TODO、DOING、DONE，各8项；负责人为虚构演示数据。标题含“登录”的任务有4项；“接口”有4项。查询“登录”模拟450ms延迟，其他查询200ms；精确查询“失败”产生模拟错误。

| 位置 | 职责 |
|---|---|
| src/seed.ts | 固定种子，不得修改来让测试通过 |
| src/api.ts | 标题/状态过滤、可取消的异步查询；不访问网络 |
| src/useTaskSearch.ts | 搜索结果、loading、error状态及请求生命周期 |
| src/query.ts | 分页纯函数；URL读取和写入为待实现入口 |
| src/App.tsx | 表单、列表、分页与页面状态 |
| tests/base.test.tsx | 已有正确行为回归测试 |

## 三、T1 异步竞态修复（40分，建议25分钟）

复现：先查询“登录”，在其结束前立即查询“接口”。较早查询可能在较新查询后结束，覆盖最新任务列表。还需考虑较早请求失败或先结束时对error、loading的影响。

要求：只有当前有效查询能提交结果、错误和结束状态。较早成功不得覆盖新结果，较早失败不得污染新错误，较早结束不得提前关闭新查询的loading。最新请求正常成功、空结果、失败和失败后的重试都须可用。组件离开时应清理本次请求生命周期。

可使用取消请求、有效性标志、请求序号或等价方案；不强制算法或特定Hook写法。模拟查询本身已支持AbortSignal；不得删除延迟或禁用错误分支掩盖竞态。

## 四、T2 URL状态同步（35分，建议35分钟）

实现查询状态分享与恢复。URL参数为`q`、`status`、`page`，例如`?q=接口&status=DOING&page=2`。

- 首次进入和刷新从URL恢复已提交搜索词、筛选与页码，搜索输入框同步；尚未提交的输入不写URL。
- 点击查询：搜索词trim，页码回1，replace当前历史项。状态筛选变化或翻页：push历史项；筛选变化页码回1。
- 浏览器前进/后退恢复输入、筛选、页码并发起对应查询。
- 缺省搜索为空，缺省/未知状态为ALL；状态仅ALL/TODO/DOING/DONE。缺省、非正安全整数、非整数或非数值页码为1。
- 当前查询成功后才按结果页数钳制越界页码；空结果保持第1页、共1页。不能使用加载前空列表或上一次查询结果提前把恢复页码改成1。规范越界页码使用replace，不增加历史项。
- 编码由URLSearchParams或等价机制处理；中文、空格、`&`不被破坏。保留无关参数和hash；默认参数可省略。
- 每页6项、顺序及已有筛选语义不变。不要求输入防抖、拖拽、编辑任务、持久化草稿或全局状态库。

## 五、T3 自动化测试（20分，建议20分钟）

`npm test`一条命令运行全部测试并以可靠退出码报告结果，能离线重复执行。保留既有7项测试。

至少增加8个有效场景：旧成功、新旧失败、旧结束时新查询仍加载、URL首次恢复、非法参数、查询/筛选重置、popstate恢复、空结果/越界页码。异步顺序使用受控Promise、模拟时间或等价可重复方法，不以固定长时间sleep作为主要断言。不复制实现充当期望值。

在公开GitHub仓库提交固定基线之后的改动，在平台填写仓库URL和首条完整Prompt。仓库提供`提交说明.md`，包含实现位置、验证命令与结果、已知未完成项。Prompt无需公开到仓库；本地提交、patch或zip仅辅助，不能替代公开仓库。
